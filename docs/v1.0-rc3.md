# Wayline V1.0 RC.3 — Beta Readiness

RC.3 在 RC.2（`7aa35b43`）基础上收敛数据正确性、断网恢复与发布工程，保持 Calendar-first 商务出行工作台的原有边界：
不自动下单、不修改 Google 日历、不扩展为泛旅游规划。

## 2. RC.3 相对 RC.2 的变更

### 数据正确性

- 行程日改为按日程自身时区计算（`src/lib/tripDay.ts`），跨时区与全天日程不再被归到错误的一天。
  影响出行归组、交通/住宿缺项判断、住宿证据与会议间通勤配对。
- 订单变更/取消通知统一按「观测时间 + 单号」归并：
  - 过期通知不会覆盖更新后的确认状态；
  - 带单号的通知只匹配同一单号，避免取消 G102 时误伤同线路补订的 G103；
  - 仅在通知丢失单号时才按线路 + 3 天内做唯一候选匹配；
  - 多个候选时标记为「待核对」，不生成虚假订单；
  - 住宿退房按自然日比较，修正「正午退房 vs 日期型订单」被误判为待核对、进而误报缺住宿的问题。
- 新增跨城端到端回归（苏州 → 上海 D1/D2），覆盖日历事件、Gmail 订单、取消 + 补订、会议冲突、
  城际最后一公里、路线时效与地图/时间线证据一致性。

### UI/UX

- 全局断网提示与恢复反馈，避免把旧路线当作当前结果；恢复后自动重新查询。
- Today 路线查询失败改为明确文案「路线暂不可用」与单一「重试路线」入口，加载态标注 `aria-busy`。
- Today 冲突在证据不足时显示「待确认」，不输出无证据的确定性结论。
- 行程订单行标注取消 / 改签 / 待核对状态，颜色之外同时保留文字，屏幕阅读器可读。

### 发布工程

- `scripts/rc-env-check.mjs`：校验 HTTPS 站点根、访问口令、Google OAuth 成对配置与回调地址、
  限流参数；只报告问题，不回显密钥。
- `scripts/wayline-backup.mjs` + `scripts/wayline-backup-drill.mjs`：备份、校验、篡改检测与恢复演练，
  演练仅使用合成临时文件。
- `deploy/compose.rc.yml`：新增健康检查，镜像标签更新为 `1.0.0-rc.3`。
- `deploy/nginx.rc.conf.example`：补齐 80→443、HSTS、安全响应头、API/静态分区限流。
- CI：生产依赖审计、环境检查、备份演练；在 `trae/v1.0-rc.*` 分支触发。
- `.gitignore` 忽略 `backups/`，备份数据不进入仓库。

## 4. 预发布部署说明

1. 在仓库之外准备私有环境文件（`WAYLINE_RC_ENV_FILE`），至少包含：
   `PUBLIC_ORIGIN`（https 站点根）、`WEB_ACCESS_PASSWORD`、`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、
   `GOOGLE_REDIRECT_URI`（`${PUBLIC_ORIGIN}/api/calendar/google/callback`）、`AMAP_WEB_SERVICE_KEY`。
2. 运行 `node scripts/rc-env-check.mjs --env-file <私有文件>`，必须输出 `PASS`。
3. `docker compose -f deploy/compose.rc.yml up -d --build`，等待 healthcheck 通过。
4. 运行 `node scripts/rc-preflight.mjs https://<staging-host>`，确认健康检查与 Origin 守卫。
5. 在 Google 控制台登记回调地址；真实 OAuth 仍需人工走通一次。
6. 首次启动前执行 `node scripts/wayline-backup-drill.mjs`；正式数据定期
   `node scripts/wayline-backup.mjs create --source .wayline-private --dest <仓库外目录>`。
7. 回滚：切回上一镜像标签重启；数据卷 `wayline-data` 保留。需要恢复时
   `node scripts/wayline-backup.mjs restore --backup <目录> --into <临时目录>` 校验后再切换。

## 5. 待决事项

- 定位文档写明「地图用高德」，代码仍以天地图做城市识别与地理编码兜底。本分支保持双供应商现状，
  未移除任一实现。是否收敛为纯高德需产品决策；在决之前，两条链路都按现有降级策略运行。

## 6. 安全与数据兼容

- 仓库不包含真实密钥、Token、Cookie、用户邮件或数据备份；`.env*`、`.wayline-private/`、`backups/` 均被忽略。
- 服务端日志不打印凭据；环境检查脚本不回显密钥值。
- 人工确认地点不会被自动识别覆盖（RC.2 已有行为，本轮回归验证保留）。
- 旧工作区与旧订单数据保持兼容；变更归并只补充状态，不重写历史来源证据。

## 7. Beta 判断

可以进入受控的 Invite-only Beta：代码质量、自动化测试、模拟浏览器与预发布检查均已通过，
具备可回滚的部署与备份路径。进入前仍需在真实 HTTPS 环境用真实凭据补验 Google OAuth、Gmail 读取、
高德/天地图与真机，并完成高德/天地图供应商收敛决策。不建议在完成上述补验前开放公开 Beta。
