## 1. Demo Workspace

入口：账号面板 →「体验演示工作区」。无需登录，不读取真实日历/Gmail。

- 独立数据空间：`demo:wayline` 本地 owner，所有键都以该 owner 结尾。
- 不写入真实账号空间；进入演示不改变当前登录账号与本地空间。
- 不请求日历状态、Gmail 同步、路线或地点供应接口；演示路线统一标记为 `estimate`。
- 一键进入、一键退出、重置：顶部 `.demo-banner` 提供「重置演示」「退出演示」。
- 退出或重置会删除所有 `*.demo:wayline` 键，并保留其他空间数据。

## 2. Action Items

`src/lib/actionItems.ts` 将 Today 与 Trips 的 `TravelRisk` 统一为 `TripAction`：

- 排序：行动生命周期（即将发生 → 未来待处理 → 时间待定 → 已过期）→ 严重度（high → medium → info）→ 相关日程开始时间（`dueAt`）→ 已确认优先于待核实 → id。
- 已过期风险仍保留在列表中，但排在所有仍有行动价值的事项之后，不会因为日期早就长期占据首位。
- 每条包含：对应日程/订单、具体问题、来源证据、下一步、不确定性标记。
- `uncertain` 覆盖：风险状态为 `uncertain`、来源 `stale`、缺少证据。
- 去重键：`类型 + 路段 + 日程集合 + 标题 + 证据来源:记录 ID（排序后）`；不同订单或会议不会被错误合并。
- 只读派生：不自动订票、不修改日历、不调用聊天 Agent。

展示：

- Today：最多 2 条紧凑行动项，附下一步按钮。
- Trips：完整列表，含相关日程、来源、待确认说明；点击下一步跳转日程或通勤详情。

## 3. UI / UX

- 保留地图优先布局，不整体重设计。
- 首屏行动项按风险与时间排序，减少在多个面板之间来回查找。
- 演示横幅固定在安全区顶部，移动端按钮保持可点面积。
- 行动项按钮最小 44px，支持键盘焦点与触屏。
- 空状态：无风险时不渲染空列表；无证据时提示「需人工确认」。

## 4. 数据与可靠性

- 演示 owner 的路线只产生 `estimate` 证据，不会伪装成高德实时路线。
- 取消通知按 `observedAt` 与邮箱同步时间比较，仅更新更新的通知，避免旧通知覆盖新状态。
- 模糊地点即使已有临时坐标，也会产生 `uncertain` 的 `missing-location` 风险，提示人工确认。
- 演示模式暂停工作区推送与 `activeUser` 持久化，避免与真实空间混淆。
- 真实账号的 Gmail/日历同步路径未改动；Demo 不触发。

### 9.1 P1 备份与恢复安全（`scripts/wayline-backup.mjs`）

| 要求 | 实现 |
| --- | --- |
| 危险恢复目标 | 拒绝文件系统根目录、用户主目录、项目根目录、项目根目录的上级，以及 `/etc` `/usr` `/bin` `/sbin` `/var` `/System` `/Applications` `/Library` 本身 |
| 目录重叠 | 备份源与目标目录、备份源与备份目录、备份目录与恢复目标之间双向拒绝包含关系 |
| manifest 路径 | 仅接受规范化 POSIX 相对路径；拒绝绝对路径、盘符、`..`、空字符、反斜杠、重复路径 |
| 异常条目 | 备份源出现符号链接或非普通文件时直接拒绝；校验时把符号链接、FIFO 等标记为问题 |
| `--force` | 目标非空必须显式 `--force`；覆盖一律走暂存目录 + 原子重命名，失败回滚旧目录 |
| 两阶段恢复 | 先恢复到目标父目录内的独立暂存目录，逐文件重算字节数与 SHA256，全部一致后才切换 |
| 一致性 | manifest 记录 `type`、`bytes`、`sha256`、`totalFiles`、`totalBytes`，校验文件数量、类型、字节数、校验和与多余条目 |

测试：`scripts/wayline-backup-safety.mjs` + `src/tests/backupSafety.test.ts`，覆盖危险目标、目录重叠、恶意 manifest、符号链接/FIFO、`--force`、只读父目录与不可读文件等部分失败场景；所有用例只使用 `mkdtemp` 创建的临时目录，不触碰真实用户目录。

### 9.2 P2 行动项生命周期

- 新增 `lifecycleOf`：`imminent`（24 小时内）、`upcoming`、`undated`、`expired`。

- UI 在 `data-lifecycle` 上标注状态，并对「即将发生」「已过期」显示可见标签。
