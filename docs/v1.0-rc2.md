# Wayline V1.0 RC.2 验收

RC.2 延续以 Google Calendar 为中心的商务出行地图。主要变化集中在订单有效状态、城际接驳证据、地点判断和预发布可运维性。开发基线为 GitHub `main` 的 `62fec0fb5d7d`。

**发布判断：可作为独立预发布候选，暂不邀请外部测试用户。** Google 正式 HTTPS 回调、真实地图数据、容器恢复和两类手机的导航回跳仍有明确验收项。

## 行程引擎

- 有效订单覆盖、取消与补订根据订单状态判断。房间取消只提示一次，跨夜住宿缺项按受影响时间段计算。仅有取消通知时，仍检查是否缺少交通或住宿。
- 会议重叠检查保留外层长会议与所有内层会议的冲突。行程时间线消除与同一条重叠提示的重复。
- 城际接驳按车次到达与会议开始，或会议结束与车次出发，计算窗口。对已确认的进出站与会议地点提供按需查路。已有直接时间冲突时避免重复接驳提示。
- 道路耗时超过可用窗口时标记风险并显示差值。耗时处于窗口内时，候车、安检、步行等未验证条件仍影响结果。路由无效或超过有效期时保留待确认状态。同步异常时保留最后可信数据并降低结论确定性。
- 风险绑定对应事件和订单，记录来源、依据及可执行操作。所用道路耗时保留供应商和查询时间。用户手动确认的地点和原始可追溯信息继续保留。

## Calendar 与 Gmail 数据质量

Calendar 覆盖过期回调、账号不匹配、空日历、已选日历、分页及增量回退、乱序取消、跨时区、撤权、限流和重启。API 遇到不完整响应时保留上次成功结果。

Gmail 用合成铁路、航班和住宿订单验证有效安排、重复、改签、取消、退款歧义和空结果。多程订单只有一封归属不明确的退款通知时，保留各段原状态，另提示待核对。本轮样本未使用真实用户邮件或日历。

## 文件与安全

- `src/lib/tripFeasibility.ts`、`tripTransfers.ts`、`businessOrders.ts` 和 `useTodayLegs.ts` 集中处理订单与道路证据，`BusinessTripConnections.tsx`、`BusinessTripCommute.tsx` 和 `App.tsx` 对应界面和状态。
- `calendarPlaces` 服务、`server/travel-services.mjs` 和地点编辑组件收紧地址确认，补上返回焦点。保留原有触控和地图优先布局。
- `server/accounts.mjs`、`server/google-calendar.mjs` 和 `server/gmail-rail-orders.mjs` 的授权路径经审查。现有账号绑定、一次性 state、PKCE 及只读范围继续使用。Gmail 仍是单独授权。
- `server/index.mjs`、`web-host.mjs`、`api-error.mjs` 和 `rate-limit.mjs` 限制跨站请求、验证请求类型、限制体积和频率、隐藏供应商错误细节。生产候选依赖选定 HTTPS 来源及访问门槛。代理路径日志省略回调参数。转发 IP 只在已启用代理信任时读取。
- 可选供应运行时对 Hono 和 Node 适配器做同主版本补丁更新。npm 对该生产依赖树报告 0 项。现有主分支的安全告警仍按其锁文件单独评估。未合并依赖机器人 PR。

## 自动化与模拟

- 基线通过 lint、test、build。RC.2 本机通过 lint、test、build，测试 78 文件、735 用例。
- `tests/browser/workspace.cjs` 在桌面 Chrome、Pixel 7 模拟 Chrome 和 iPhone 13 模拟 WebKit 测试。包含无真实凭证的授权与日历模拟，交通方式及道路故障，地点修正和回跳。新增跨城案例沿会议同步、订单冲突、取消、缺项、补订和查接驳执行。

## 预发布和回滚

1. 准备独立 HTTPS 测试域名、隔离网络和独立 Docker 项目及数据卷。复制 `deploy/rc.env.example` 至私有位置并限制读取权限，配置 `PUBLIC_ORIGIN`、访问密码、独立 Google 测试应用以及测试账号。Chrome 或 Safari 预检先确认访问门槛生效。
2. 在测试 Google Web 客户端登记该域名的 `/api/auth/google/callback` 和 `/api/calendar/google/callback`，启用测试 Calendar API。Gmail 在需要验收时单独启用并保持既有只读范围。用个人和 Workspace 测试账号验证隔离、登录拒绝、日历选择、时区、撤权和重连。取消及改期用测试人员预置的事件或供应夹具。
3. 有获准的免费地图配额后，填服务端 Key，把受域名限制的浏览器底图参数提供给 Compose 构建。用 `WAYLINE_RC_ENV_FILE=/private/path/rc.env docker compose -p wayline-rc2 -f deploy/compose.rc.yml config --quiet` 检查配置，再用同样前缀执行 `up -d --build`。用 `deploy/nginx.rc.conf.example` 配置反代与证书，先运行 `nginx -t`。对独立域名运行 `node scripts/rc-preflight.mjs https://your-staging-origin.example --preview`。
4. 验证真实底图及道路查询，运行公开 POI 实测。iOS Safari、Android Chrome 各走一遍地点纠错、切换路线、地图 App 跳转及返回、刷新恢复、断网与重连。用键盘和系统读屏核查登录、地图旁时间线及错误重试。
5. 备份前停止写入进程。对卷及匹配的加密密钥安全快照，另存当前镜像标识与代理配置。重启确认数据仍可读。若候选失败，恢复先前镜像和代理配置，先用备份复制卷验证，再切回正常流量。保留新旧原始数据卷。导出的用户备份也先在单独浏览器配置中导入核对。
6. 全部补齐后再开放 Invite-only Beta。CI 通过、Google 真实回调和撤权、真实地图限制条件、双系统真机回跳、容器持续运行与回滚演练分别签字记录。
