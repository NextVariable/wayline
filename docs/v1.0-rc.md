# Wayline V1.0 RC.1

Wayline 以 Google 日历中的商务安排为起点，将支持来源的订单、个人地点和地图路线整理为工作台。今天显示下一站和逐段通勤。行程显示跨城出差的时间线、可确认的冲突和下一步。地点保留收藏、地点别名、图层和足迹。

## 架构、数据与兼容

- `server/google-calendar.mjs` 读授权选定的日历。后台在原窗口内带 `updatedMin` 增量合并，游标为上次成功请求的开始时间，重叠 60 秒。首读、更换日历、用户手动同步、增量被上游拒绝或约每十分钟时全量重扫。分页完成才替换，取消记录删同一个事件 ID。失败保留快照和游标。被改到窗口外的事件由定期或手动全量纠正。范围沿用过去 30 天和未来 180 天，未启用无时间边界的同步令牌模式。[Google Calendar 查询参数](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)
- `server/gmail-rail-orders.mjs` 继续从支持的结构提取订单。日期、端点、接收时间与变更类型用于归组和版本判定。原始邮件、认证头、旅客信息和订单编号不进入行程响应。通知仅在参考编号匹配时作为取消或改签证据，无可靠关联时只标待核对。旧缓存按需重读变更通知，解析失败保留上次状态。撤权后保留既有快照并请求重连。单封验收模式的记录留在 Gmail 来源页。
- `src/lib/tripDomain.ts` 复用持久化的 `CalendarEntry` 和 `Place` 作为 CalendarEvent 和 Place。事件继续按来源 ID 识别，Google 版本来自更新时间。地点保留原坐标、手动确认和别名。Trip 由第一条归组日程的 ID 和拆合规则派生，包含统一时间线和 TripSegment。Segment 对应市内通勤、城际、住宿，绑定事件和预订。Booking 保留标准化端点和时间，合并来源证据，并承载有效、取消、改签和待核对状态。
- RouteEvidence 记录地图模式、路程耗时、坐标和查询时刻。TravelConstraint 绑定明确的事件 ID 与最早出发或最晚到达时间。TravelRisk 含 ID、严重度、不确定状态、相关事件及路段、证据、依据和过期标记。ActionItem 指向日程核对、地点纠错、路线或预订安排。SourceProvenance 记录来源、记录 ID、观测时间、可信度和新鲜度。内部联系 ID 不用于页面展示。
- `src/lib/tripIntelligence.ts` 集中调用现有常驻城市推断、日历关联、拆合规则和地点派生。日历改期或地点更新，重新归组并刷新相应计划。根据事件时间、坐标、已选方式形成查询参数和版本。任务、路线和风险视图按账号隔离。固定备份版本、存储键和浏览器历史继续沿用。V1 视图模型在读取时派生。服务端游标为可选新增字段，旧连接缺字段时进行第一次有界完整读取。V0.3 代码可读取同一快照和原数据。
- `src/App.tsx`、TodayPanel、BusinessTripsPanel、BusinessTripCommute、BusinessTripConnections、Sidebar 使用同一模型并保留既有地图和导航入口。取消或需核对的订单保留在时间线，地图订单点只使用当前可用证据。保留 OAuth、工作区冲突处理、加密持久化、高德和现有免费供给。

## 可行性规则

| 规则 | 依据与呈现 |
| --- | --- |
| 日程重叠 | 日历中一场尚未结束而另一场已经开始。识别长会议覆盖若干较短会议的情况。日历失效时降为待核实。 |
| 通勤时间不足 | 日历间隔减路线时长，差值为负则提示不足。中间线上会议会占用时间。路线请求失效、无查询时间、估算数据或日历异常时不产生确定判断。 |
| 地点缺失 | 日程缺有效坐标且需要实体地址，提示从角落进入核对。保留线上或用户忽略的日程规则。 |
| 已订交通冲突 | 发车或起飞早于上一场结束，或到站晚于会议开始。参考时间缺失或来源过期时显示待核实。 |
| 城际接驳 | 识别城际路段及会议约束。缺到达时刻或最后一公里路线时提示核对，保留不确定状态。 |
| 取消、改签 | 可确认的通知影响对应预订。不明确的通知提示核对，等待有效的新确认。 |
| 行程缺项 | 当前选定数据源找不到可关联的交通或住宿时，提示查证或使用既有参考入口。 |

日历快照超过 10 分钟、Gmail 快照超过 30 分钟或存在撤权、部分数据、失败时降级。高德查询证据最多用于 30 分钟内的判断。高德时长是查询参考，未来交通状态和到站办理时间仍待出行当日核对。从未获取的时长保持未知。

## 安全与隐私核对

- 授权沿用 Google 登录与两个 Calendar 只读 scope、Gmail 只读独立同意。邮件和日历取数为读取操作。保留 state、PKCE、回调归属、限流、加密及 Secure/HttpOnly Cookie 的基线回归。
- 本轮验证有界查询、取消增量更新、游标回退、Gmail 失效与私密字段剔除。已有双账户、快照恢复、工作区冲突和 OAuth 回调测试随完整套件运行。
- OAuth Token、服务端密钥、私有数据与静态文件继续分离。应在生产代理验收日志路径脱敏、请求头脱敏、缓存、Cookie 及密钥挂载。真实 Google Workspace 主历标识与登录邮箱不同等边界仍需单独核对。

## 浏览器回归

`tests/browser/workspace.cjs` 可用系统 Chrome 和 Playwright WebKit 运行。以没有私人配置的工作目录运行 `PORT=18945 HOST=127.0.0.1 node server/index.mjs`，再执行 `node tests/browser/workspace.cjs`。已有独立 Playwright 安装时可通过 `WAYLINE_PLAYWRIGHT_MODULE` 指定其路径。脚本将 Google、Gmail、地图和导航替身放在独立会话，外部网络访问被拦截。

桌面 Chrome、Pixel 7 配置的 Chrome 和 iPhone 13 配置的 WebKit 验证了登录授权模拟、日历选择与失败重试、地图与时间线、供应失败后断网恢复、交通方式切换、取消及预订冲突、导航返回恢复、地点别名查看与移除。移动端导航触点和横向溢出也已检查。真实地图 App 与辅助技术由真机验收。
