# Wayline 阶段性范围裁决与未决事项（M5 收口）

日期：2026-11-25  
分支：`feat/ai-native-mvp`  
状态：**工程记录，不是产品批准文件**。G0 仍未批准，PRD 仍未冻结。

## 1. 长期定位与阶段范围

长期定位：**AI-native Business Travel Workspace**。

当前阶段仅支持**中国大陆商务出行**。这是阶段性市场与技术实施范围，不是永久地域限制，也不代表放弃未来海外市场。

### 当前范围

- 中国大陆城市内及跨城市商务出行。
- 高德地图作为唯一正式支持的地图、POI、路线规划供应商。
- DeepSeek API 作为当前唯一 AI 模型供应商（`deepseek-flash`，`https://api.deepseek.com`，thinking disabled）。
- Google Calendar、Gmail、ICS、自然语言及手动录入作为信息来源。
- 响应式 Web 应用。
- Today、Trips、History 三个核心工作台。

### 暂缓范围

- Google Maps 接入；海外地图与路线规划。
- 港澳台及海外出行场景的正式支持与验收。
- 多地图供应商切换、海外交通服务适配。
- 全球化部署及完整国际化。

### 实现约束

- 不为未来海外扩展预建多地图供应商抽象层。
- 现有海外相关代码保留为非启用资产，不做无关删除或重构。
- 不把“中国大陆限定”硬编码为不可逆限制；保留时区、坐标、城市与数据来源的扩展能力。
- Google Calendar、Gmail、Google OAuth 与 Google Maps 是不同服务；暂缓 Google Maps 不取消其他 Google 服务。

## 3. R02–R05 未决问题

以下为工程侧整理，**推荐裁决不等于已批准**。

### R02 本地删除后的再同步行为

| 项目 | 内容 |
| --- | --- |
| 原始需求 | IN05、BR03/05/06、DA01/02、AC18：需定义用户删除导入记录后，重复/增量/全量同步、来源更新、断开重连的行为。 |
| 当前实现 | 2026-11-25 已加入来源墓碑：来源取消/窗口内消失的事件标记 `google.deletedAt`，退出活动视图但保留 History；用户“从 Wayline 移除”按来源键（calendarId + eventId）建立抑制，跨重连仍生效。尚未提供显式“重新导入”入口；墓碑清理策略尚未产品确认。 |
| 推荐裁决 | 用户删除默认建立来源键抑制；仅在用户显式“恢复/重新导入”时解除；来源新版本默认不自动复活用户已删记录。墓碑保留 90 天，其后只保留最小抑制键，不含正文。 |
| 影响 | 若不裁决，删除后可能被误认为永久删除，或重连后记录复活；影响 AC07/AC18 的验收表述与隐私期限。 |

### R03 出发提醒窗口的时钟锚点

| 项目 | 内容 |
| --- | --- |
| 原始需求 | RT09 定义 `latest_departure`；RT12 从“可离开时刻前 10 分钟”开始提示，审查认为锚点错误。 |
| 当前实现 | 代码以 `latestDeparture` 与 `availableMinutes` 计算风险与出发建议；尚未按“提前 N 分钟”单独拆分提醒窗口，也未有后台提醒通道。 |
| 推荐裁决 | 以 `latest_departure` 为提醒锚点；提前量由 D04 决定；时间不足属于路段风险，不受临近窗口限制；继续声明基于计划起点、非 GPS、非迟到事实。 |
| 影响 | 若维持现状，UI 只在页面打开时显示建议，不会提前刷屏，但也没有“该出发了”的主动提醒；影响 AC15/AC24 的完整表述。 |

### R04 Trip 时区与状态切换

| 项目 | 内容 |
| --- | --- |
| 原始需求 | Trip 字段、TR03/05、U02：需唯一规则定义 Trip 时区、草稿转 upcoming、全取消转 canceled 及恢复。 |
| 当前实现 | 展示与归组统一按 `Asia/Shanghai`；Trip 状态主要由“结束日期早于今天”推导 History；尚无独立 draft/upcoming/active/canceled 状态机，也无跨时区 Trip 归档规则。 |
| 推荐裁决 | 当前阶段 Trip 展示与归档时区固定为 `Asia/Shanghai`，同时保留事件原始时区字段；全部有效内容取消时标记 canceled，新增有效项可恢复；跨时区日期比较在引入境外场景前再定义。 |
| 影响 | 国内 Beta 可用；若未来展示境外行程，需先补状态机与时区规则，否则可能出现提前/推迟归档。 |

### R05 提醒“已过时”生命周期

| 项目 | 内容 |
| --- | --- |
| 原始需求 | Insight 枚举、AI05、AC15：需区分 resolved/dismissed/superseded 与“问题未解决但已失去行动价值”。 |
| 当前实现 | 行动项有 open/resolved/dismissed 状态与到期清理；过去会议仍可能出现在提示集合中，缺少独立的“已过期”展示与排序。 |
| 推荐裁决 | 增加“已过期”行动状态：纯已结束会议风险退出当前突出区但保留历史；退款/订单核对可继续待办并标逾期；不照搬 RC.4 内部枚举。 |
| 影响 | 不裁决则过去事项可能挤占下一站风险，影响 Today 的信息优先级与 AC15。 |
