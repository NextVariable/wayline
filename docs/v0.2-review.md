# V0.2 日程地图验收

基于公开仓库 main 的 3ba30e3。按 PRODUCT.md、DESIGN.md 和定位文档核对登录、日历连接、地点解析、地图和导航。原桌面归档与公开仓库是两个不同的 Git 仓库。本轮使用独立检出、临时存储和合成会议。

## 能力核对

| 能力 | 结论和证据 | 未覆盖范围 |
| --- | --- | --- |
| 登录与权限 | 已实现。账号服务验证浏览器绑定的 OAuth state 和 PKCE，日历与 Gmail 各自只读授权。账号服务和日历服务回调有独立回归。 | Google 真实同意页及生产域名回调待验。 |
| 日历同步 | 已实现。后台定期读取所选日历在过去 30 天及未来 180 天内的分页快照，完整读取后替换。界面轮询；会议改期、换址、取消有回归。 | 登录后仍需连接并选择日历。后台需要持续运行。 |
| 地点识别 | 部分自动。可信的同城唯一匹配可自动上图，多义地点交给用户确认；账户间缓存隔离。 | 模糊地名、供应商返回空结果仍需手动确认。旧事件中已经保存的点位没有批量重算。 |
| 地图、路线与风险 | 已实现当天或下一有地点日程的时间线、逐段切换、路线聚焦，以及根据可用时间判断迟到。两场之间存在未定位的实体会议时不跨过去连线。 | 本轮浏览器使用受控路线响应；目标域名真实底图、公交供应和限流需独立验收。 |
| 手机导航 | 页面和导航链接已实现。手机模拟检查高德链接的模式、调用 App 参数和触点尺寸。 | iOS Safari、Android 实机、已安装和未安装地图 App 的系统行为待验。 |
| 数据保护 | 代码和现有回归覆盖会话绑定、账号隔离、过期授权、同步冲突、本地持久化失败与恢复。浏览器测试未接触实际业务存储。 | 本轮没有生产双账号、跨设备或线上日志审计。 |
| 仍缺的体验 | 首次登录到首次上图仍有单独选日历的步骤。无坐标的当天事件不能完整呈现在地图时间线上。 | 后续应验证首次使用和纠错可发现性。 |

## 修改清单

| 文件 | 原因与改动 |
| --- | --- |
| server/accounts.mjs | 登录原先重复请求日历权限且保存未被后续连接使用的令牌。普通登录现在只请求身份，不强制重复同意，不保存新的登录令牌。日历和 Gmail 保留独立连接。 |
| server/google-calendar.mjs | 读取事件时指定 UTC，拒绝无偏移的模糊时刻，避免随服务器时区静默变化。 |
| src/lib/useGoogleCalendar.ts、src/lib/googleCalendarSync.ts | 区分合法空快照和缺字段的异常快照，后者保留原数据。 |
| src/components/GoogleCalendarConnection.tsx | 首次检查连接失败后可直接重试。 |
| server/calendar-places.mjs、src/lib/geoSearch.ts | 支持省份开头的城市范围，同名跨城和仅部分匹配地址的结果交给用户选择。旧自动查询缓存不再沿用，用户保存的数据保留。 |
| src/lib/calendarPlaces.ts、src/lib/useCalendarPlaces.ts | 隔离超长地点文字，恢复联网时重新解析；全天日期和夏令时窗口按本地日历日计算。 |
| server/travel-services.mjs | 拒绝无效耗时、非零距离零耗时、不完整坐标和线形，避免错误的准时判断。 |
| src/components/TodayPanel.tsx、src/styles/globals.css | 已查询路线显示来源与查询时间，手机交通方式、重试和导航触点至少 44px。 |
| src/tests 下的 accountsServer、googleCalendarServer、googleCalendarSync、calendarPlaces、calendarPlacesServer、calendarSearchCity、todayPanel、travelServices | 更新登录权限断言，并补充上述异常和显示回归。 |

## 本轮验证

- 基线 lint、688 项测试、生产构建通过。修改后 lint、74 个测试文件共 699 项、TypeScript 与 Vite 生产构建通过。全天日期用例另在洛杉矶时区执行通过。
- 独立 Chrome 加载实际生产构建。桌面 1440px、iPhone 13 与 Pixel 7 模拟设备分别使用合成 Google 状态、地点和路线响应，无外部地图瓦片或账号访问。
- 两场会议相隔 20 分钟。路线首次返回 503，点击重试后公交 30 分钟显示差 10 分钟，切换打车 15 分钟后风险解除。核对了导航链接的方式、手机唤起参数、触点和页面宽度。
- 刷新后返回缺字段的快照，两场原日程保留；随后改期、换址，显示新地点并重新判定风险；取消一场后相关路段消失，再返回空快照，无残留路段。该轮通过刷新拉取变化，未测量生产轮询延迟。

## V0.3 优先顺序

1. 在目标 HTTPS 域名以只读测试账号走完首次登录、选历、上图、撤销授权和重连，记录每个步骤的等待时间。用两个独立账号检查切换与隔离。
2. 用真实但非私人地址评估地点解析的正确率和待确认比例，优先覆盖重名会场、园区内楼栋和跨城会议，再验证纠错后回到原时间线。
3. 将同一组路线放到实际 iPhone 和 Android 上，测试地图应用安装与未安装、返回网页恢复当前路段，以及供应商超时后的恢复。
